## 数据读取策略

行情数据由 `jobs/` 模块每日写入 PostgreSQL，`backend/` **只读不写**，所有行情接口直接查 DB 返回，无需缓存层。

---

## Redis（暂不引入）

行情数据每日一次写库，接口直接查 DB，**不需要 Redis 做行情缓存**。

Redis 唯一潜在用途是 JWT 登出黑名单，可用以下替代方案推迟引入：
- 登出时在 DB `user` 表写 `token_revoked_at` 字段，`deps.py` 校验 token 签发时间是否早于该字段
- 性能略低但无需额外依赖，用户量小时完全够用

---

## 认证与权限设计

- **JWT**：登录返回 access_token（HS256，有效期 8h）
- **白名单**：`user.is_whitelisted = True` 才允许访问数据接口
- **黑名单**：`user.is_blacklisted = True`，`deps.py` 中间件直接返回 403
- **登出**：在 DB `user` 表写 `token_revoked_at`，`deps.py` 校验 token 签发时间是否早于该字段，无需 Redis
