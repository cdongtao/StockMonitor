# Sub-Agent 并行开发规范 — Stock Monitor

## 概述

本项目支持多个 AI Agent 并行开发，每个 Agent 负责独立模块，通过严格的目录所有权和启动顺序避免冲突。

---

## Agent 定义

| Agent 名称 | 负责模块 | 独占目录 |
|------------|----------|----------|
| **db-agent** | 数据库 Schema + Alembic 迁移 | `backend/alembic/` `backend/app/models/` |
| **jobs-agent** | 数据采集 + 定时任务 | `jobs/` |
| **backend-agent** | FastAPI 接口 + 业务逻辑 | `backend/app/api/` `backend/app/services/` `backend/app/schemas/` `backend/app/core/` |
| **frontend-agent** | React 前端页面 + 组件 | `frontend/` |
| **test-agent** | 测试用例 | `backend/tests/` `jobs/tests/` `frontend/src/__tests__/` |

---

## 启动顺序

```
Step 1: db-agent        ← 必须最先完成，其他 Agent 依赖 Schema
         ↓
Step 2: jobs-agent      ← 并行启动（依赖 DB Schema，不依赖 backend）
         + backend-agent ← 并行启动（依赖 DB Schema，不依赖 jobs）
         ↓
Step 3: frontend-agent  ← 依赖 backend API 接口定义完成后启动
         ↓
Step 4: test-agent      ← 各模块功能完成后并行补测试
```

**强制规则**：db-agent 未完成前，其他 Agent 不得启动。

## 各 Agent 职责详情

### db-agent
- 根据 `5.db-design.md` 创建所有 SQLAlchemy ORM 模型
- 创建初始 Alembic 迁移文件（`backend/alembic/versions/`）
- 完成后输出：所有 models 文件 + 可运行的 `alembic upgrade head`
- **禁止**：修改业务逻辑、创建 API 路由

### jobs-agent
- 根据 `4.job-design.md` 实现所有数据同步任务
- 实现 `data_sources/`（东方财富、Tushare 适配器）
- 实现 `tasks/`（sync_market, macd, alert_checker, intraday_monitor, backtest）
- 实现 `services/notification.py`（邮件推送）
- **禁止**：修改 `backend/` 任何文件、写入 users/alert_rules 表

### backend-agent
- 根据 `2.backend-design.md` 实现所有 FastAPI 接口
- 实现认证（JWT 签发/校验）、权限校验（`deps.py`）
- 实现 `schemas/`（所有 Pydantic 请求/响应 Schema）
- 实现 `services/`（market_service, alert_service）
- **禁止**：修改 `jobs/` 任何文件、写入行情数据表

### frontend-agent
- 根据 `3.frontend-design.md` 实现所有页面和组件
- 实现 `api/` 层（所有 HTTP 请求封装）
- 实现 `hooks/`（业务逻辑）、`components/`（纯展示）
- 参考 `9.frontend-mock-data.md` 对齐数据结构
- **禁止**：修改 `backend/` 或 `jobs/` 任何文件

### test-agent
- 为每个已完成模块补充测试用例
- jobs 测试：正常写入 + API 返回空数据两种场景
- backend 测试：200 正常 + 401 未登录 + 200 空列表三种场景
- **禁止**：修改非 tests 目录的业务代码

## 冲突预防规则

1. **一个文件只能由一个 Agent 拥有**，不得跨 Agent 修改同一文件
2. **db-agent 完成前**，其他 Agent 只能读取 `knowleage/` 文档，不得写代码
3. **共享 models**：jobs-agent 和 backend-agent 都需要读取 ORM 模型，但只有 db-agent 可以修改 `models/`
4. **接口契约**：backend-agent 完成 Schema 定义后，frontend-agent 才能开始对接，以 `8.backend-mock-data.md` 为契约文档
5. **任何 Agent 修改 API 接口或 Schema**，必须同步更新对应 mock data 文件（`8.backend-mock-data.md` / `9.frontend-mock-data.md`）
6. **架构文档只读**：`knowleage/1.architecture.md` 阶段 checklist 由主 Claude 更新，子 Agent 不得修改

