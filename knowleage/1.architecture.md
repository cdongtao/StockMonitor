# Architecture — Stock Monitor

## 项目概述

**Stock Monitor** 是一个 Web 端股票监控工具。
## 用户管理服务（User Management）
用户可以登录验证服务。
## 股票管理服务（Stock book Management）
用户可以订阅或取消订阅股票代码。
处理用户的订阅请求，并将订阅信息发送给股票数据获取服务。
提供 API 接口，供前端应用与用户管理服务进行交互。
## 股票数据获取服务（Stock Fetcher）
定时从公开 API 获取订阅股票的最新数据。
根据市场状态判断是否继续获取数据，并将数据发送到股票数据处理服务。
接收市场状态的更新，并根据状态调整数据获取逻辑。
## 股票数据处理服务（Job Stock Processor）
对从数据获取服务接收到的股票数据进行清洗和解析。
基于清洗后的数据执行预定义的策略，判断是否需要触发通知。
将市场状态发送回股票数据获取服务，以控制数据获取流程。
## 通知服务（Notification）
接收来自股票数据处理服务的通知请求，并将通知发送给用户。
可以使用不同的通知方式，如短信、电子邮件或推送通知。
## 管理监控服务（Admin Monitoring）
提供系统状态监控功能，确保各微服务正常运行。
提供接口供管理员查询和管理系统状态。

## 系统模块划分

| 模块 | 职责 |
|------|------|
| `backend/` | FastAPI HTTP 接口、用户认证、告警规则 CRUD |
| `jobs/` | 每日定时拉取行情数据、告警检测、邮件推送（独立进程） |
| `frontend/` | React Web 界面 |

**数据流：**
- `jobs/` 每日收盘后调用东方财富 API → 写入 PostgreSQL
- `frontend/` → `backend/` API → 从 PostgreSQL 读取返回

## 消息推送功能规则

**支持指标：**
- 价格突破：高于 / 低于设定价格
- 涨跌幅阈值：当日涨跌幅超过设定百分比（如 +5% / -3%）
- MACD 金叉 / 死叉：DIF 与 DEA 交叉时触发

**规则约束：**
- 同一股票最多设置 10 条告警规则
- 告警触发后自动变为「已触发」状态，不自动重置，需手动重启

**推送方式：**
- 邮件（SMTP，必选）
