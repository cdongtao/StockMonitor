# Job Design — Stock Monitor

## 职责

`jobs/` 是独立运行的 Python 进程，包含两类独立任务：

| 类型 | 触发方式 | 说明 |
|------|----------|------|
| **盘后数据同步** | 每日收盘后定时执行 | 从东方财富 / Tushare 拉取当日数据写入 PostgreSQL |
| **盘中实时监控** | 交易时段每 1 分钟轮询 | 读取监控表，拉取盘中实时数据，触发条件满足时推送提醒 |

与 `backend/` 共享同一个 PostgreSQL 数据库，但**各自独立部署、互不依赖**。

## 目录结构

```
jobs/
├── main.py                  # 入口：启动 APScheduler，注册所有任务
├── core/
│   ├── config.py            # 环境配置（复用 .env，与 backend/ 同一份）
│   └── database.py          # 数据库连接（async SQLAlchemy）
├── data_sources/            # 数据源适配器
│   ├── base.py              # 抽象基类：定义 fetch() 接口
│   ├── eastmoney.py         # 东方财富 HTTP 适配器（B1–B10、B18，接口详见 WebScreen/api/）
│   └── tushare.py           # Tushare Pro（历史 K 线，供 MACD 计算用）
├── tasks/
│   ├── sync_market.py       # 【盘后】每日行情数据同步（B1–B10、B18）
│   ├── macd.py              # 【盘后】MACD 计算（B15）
│   ├── alert_checker.py     # 【盘后】告警规则检测（B14）
│   ├── intraday_monitor.py  # 【盘中】每 1 分钟轮询监控表，推送实时提醒
│   └── backtest.py          # 【按需】单股 MACD 策略回测（B17）
└── services/
    └── notification.py      # 邮件推送（B16，盘后/盘中均可调用）
```

## 数据同步策略

东方财富 API **每天只调用一次**，收盘后按序执行：

| 任务 | 触发时间 | 对应功能 |
|------|----------|---------|
| 涨停板 + 伏击数据同步 | 15:35 | B1、B4 |
| 龙头 + 个股原因同步 | 15:40 | B2、B5 |
| 板块情绪 + 净流入同步 | 15:45 | B7、B10 |
| 期货品种价格同步 | 15:50 | B8 |
| 龙虎榜数据同步 | 15:55 | B18 |
| 历史 K 线同步（Tushare） | 16:00 | B6、B15 原始数据 |
| 告警检测 + 邮件推送 | 16:30 | B14、B15、B16 |

写入方式：`upsert by date`，重跑同一天不会产生重复数据。

## 盘后告警检测策略

- **触发时机**：每日行情数据同步完成后（约 16:30）统一跑一次
- **检测逻辑**：读取 DB 中所有状态为「启用」的告警规则，逐条比对当日数据（价格突破、涨跌幅、MACD 金叉/死叉）
- **触发后**：将规则状态更新为「已触发」，调用 `notification.py` 发送邮件，**不自动重置**

---

## 盘中实时监控策略

- **触发时机**：交易时段（09:30–15:00）每 1 分钟执行一次
- **数据来源**：读取 DB 监控表（用户配置的自选股列表），调用东方财富实时接口拉取盘中报价
- **检测条件**：价格突破（高于 / 低于设定价）、涨跌幅超过设定百分比
- **检测逻辑**：逐条比对监控表中设定的条件，满足则立即推送提醒
- **与盘后告警的区别**：盘中监控是实时报价触发，盘后告警是收盘后基于当日最终数据触发
